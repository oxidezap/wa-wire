# @oxidezap/wa-wire-ts

The wa-wire boundary format and capability vocabulary, in TypeScript.

Its own package rather than part of an adapter, because two adapters need it and
they are both TypeScript.

## Why the format is written three times and not four

An adapter runs inside its engine, so the boundary is implemented once per
*language*: Rust for `whatsapp-rust`, TypeScript for `zapo` and Baileys, Go for
`hypermeow`. Three descriptions of one format that are only ever tested
separately are three formats waiting to diverge, which is why
[cross-language fixtures](../../crates/wa-wire-conformance/tests) are written by
one and read by another.

A fourth writing in a language that already has one would be a description
nobody checks against the others. So the second TypeScript adapter shares this
rather than copying it — which is what this package was extracted for.

## What is here, and what is not

Here: the envelope layout, the recording container, the nine capability
identifiers, and the checks that hold an adapter to what it declared.

Not here: any adapter's own declaration. The vocabulary is the contract's; what
an adapter *has* is the adapter's, and lives with it. An earlier version of this
code had `zapo`'s `INFO` inside the shared module and a `has()` that closed over
it — which read as "the adapter" when there was only one, and became wrong the
moment there were two.

Nothing here imports an engine. That is what makes it shareable, and also what
lets its fixtures be regenerated by anyone without one.
